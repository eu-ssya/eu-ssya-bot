# 모임통장(Wallet) 기능 디자인 — eu-ssya-bot

**작성일**: 2026-05-25
**상태**: Design (브레인스토밍 완료, 사용자 승인 대기)
**대상 파일**: `D:\dev\eu-ssya-bot\bot.py` (수정) + `D:\dev\eu-ssya-bot\wallet_cog.py` (신규)

## 1. Summary

eu-ssya-bot에 **모임통장** 기능을 추가한다. 스터디·소규모 개발자 커뮤니티의 **운영비를 투명하게 관리**하기 위한 도구로, 한 디스코드 서버에 단 한 채널을 모임통장으로 등록하고 그 채널 내에서 입금·출금을 기록한다. 잔액은 **채널 이름에 실시간 노출**(`💰-285,000원`)되고, 모든 거래는 채널에 자동 메시지로 ledger처럼 누적된다. 등록은 **서버 관리자(Discord Administrator)만** 가능, 조회는 모든 멤버. 카테고리 없는 자유 메모 + 일단위 날짜 입력 + 임베드 UI 기반 수정/삭제(hard delete) 지원. Cog 패턴으로 `wallet_cog.py`에 분리되며 기존 RSS 봇 동작은 일체 영향 받지 않는다. KRW(원) 정수만 지원. 통화·카테고리·통계·페이지네이션 등은 명시적 out of scope.

## 2. Mental Model & Use Case

### 2.1 Use Case

소규모 개발자 스터디 커뮤니티의 운영비 관리:

- **입금원**: 보증금, 지각 벌금, 결석 벌금, 주차별 벌금 등
- **출금처**: 회식, Discord 부스트, 멤버 선물 등
- **운영진**: Discord Administrator 권한자(들). 일반 멤버는 조회만.
- **투명성 우선**: 모든 거래가 채널에 자동 메시지로 즉시 공개됨.

### 2.2 핵심 결정

| 결정 | 내용 | 근거 |
|------|------|------|
| 소유 단위 | **공유 통장** — 채널 1개 = 모임통장 1개 | 커뮤니티 운영비 use case |
| 다중 채널 | **한 서버에 1개만** | 사용자 명시 |
| 권한 모델 | Discord Administrator만 등록·입금·출금·수정·삭제 | 운영비 보호 + 단순성 |
| 통화 | KRW 정수 원만 | 사용자 명시 |
| 카테고리 | **없음** — 자유 메모(최대 200자) | 사용자 명시 |
| 잔액 표시 | **채널명**에 `💰-285,000원` 포맷 | 사용자 명시 (E 포맷, 워딩 없음) |
| 거래 가시화 | **자동 메시지** 한 줄로 채널 = ledger | 사용자 명시 (옵션 A) |
| 미래 날짜 | **허용** | 사용자 명시 |
| 오버드래프트 | **거부** — 잔액보다 큰 출금 차단 | 사용자 명시 |
| 삭제 정책 | **Hard delete** — JSON 제거 + 채널 메시지 삭제 | 사용자 명시 |

### 2.3 명시적 비목표 (out of scope)

- 다중 통화 (USD/EUR/JPY 등)
- 카테고리/태그 시스템
- 월별/주별 통계, 자동 요약
- 차트, CSV 익스포트
- 다중 가계부(한 서버 내) — 1개만 허용
- 사용자별 개인 지갑
- pytest 풀스위트(검증은 static + pure function unit + manual)
- SQLite 마이그레이션, 모듈 추가 분리
- `/모임통장 balance`, `/모임통장 list`, `/모임통장 stats`, `/모임통장 reset`, 짧은 ID 노출
- 다국어
- 페이지네이션(거래 < 25건/일 가정), 정산 보고서, 잔액 그래프

## 3. Commands & UX

### 3.1 명령어 세트 (4개)

모두 한국어. 파라미터도 한국어. Discord slash command name은 한글 unicode letter 지원.

#### `/모임통장 등록`
- 인자: 없음
- 동작: 현재 채널을 모임통장으로 등록. 초기 잔액 0. `original_name`은 등록 시점 채널명 캡처.
- 권한: Administrator
- 응답: `"모임통장을 시작합니다. 초기 잔액: 0원. 채널 이름이 곧 갱신됩니다."` (non-ephemeral)
- 거부 케이스:
  - DM 채널: `"이 명령은 서버 채널에서만 사용할 수 있습니다."`
  - 비텍스트 채널: `"일반 텍스트 채널에서만 사용할 수 있습니다."`
  - 봇에 `Manage Channels` 권한 없음: `"봇에 '채널 관리' 권한이 필요합니다."`
  - 일반 멤버: `"이 명령은 서버 관리자만 사용할 수 있습니다."`
  - 이 서버에 이미 다른 채널에 모임통장 등록됨: `"이 서버에는 이미 <#기존채널> 에 모임통장이 등록되어 있습니다."`
  - 이 채널이 이미 등록됨: `"이 채널은 이미 모임통장으로 등록되어 있습니다."`

#### `/모임통장 입금 금액:<int> [메모:<str>] [날짜:<YYYY-MM-DD>]`
- 인자:
  - `금액` (필수, int, 1 이상)
  - `메모` (선택, str, 기본 "", 최대 200자)
  - `날짜` (선택, str, 기본 오늘 KST, 형식 `YYYY-MM-DD`)
- 동작: 거래 추가(kind=income), `balance += 금액`, 채널에 자동 메시지 송신, 채널명 갱신 큐잉.
- 권한: Administrator
- 응답 (ephemeral): `"입금 +50,000원 기록 완료. 현재 잔액: 285,000원"`
- 자동 메시지 (non-ephemeral): `"📥 +50,000원 · 지각벌금 홍길동 · 2026-11-28 · 잔액: 285,000원"`

#### `/모임통장 출금 금액:<int> [메모:<str>] [날짜:<YYYY-MM-DD>]`
- 인자: 입금과 동일 형식
- 동작: 거래 추가(kind=expense), `balance -= 금액`, 채널 자동 메시지, 채널명 갱신 큐잉.
- 권한: Administrator
- 거부 케이스:
  - `금액 > balance`: `"잔액(285,000원)보다 큰 출금은 등록할 수 없습니다."` (overdraft 금지)
- 응답 (ephemeral): `"출금 -15,000원 기록 완료. 현재 잔액: 270,000원"`
- 자동 메시지: `"📤 -15,000원 · 디스코드 부스트 · 2026-11-26 · 잔액: 270,000원"`

#### `/모임통장 관리`
- 인자: 없음
- 동작: 임베드 UI로 3단계 수정/삭제 인터페이스 진입
- 권한: Administrator
- View timeout: **10분** (600초)
- 응답: 첫 화면 ephemeral (관리자만 볼 수 있음)

### 3.2 자동 메시지 포맷 (옵션 A — 한 줄 plain text)

```
📥 +50,000원 · 지각벌금 홍길동 · 2026-11-28 · 잔액: 285,000원
📤 -15,000원 · 디스코드 부스트 · 2026-11-26 · 잔액: 270,000원
```

- 줄 시작 이모지로 입출금 시각 구분 (`📥` 입금 / `📤` 출금)
- 금액은 부호 포함 (+/-)
- 메모가 빈 문자열이면 메모 부분 생략 (`· · ` 안 나옴)
- 날짜는 ISO `YYYY-MM-DD` 형식 (full date)
- 잔액은 거래 적용 후의 현재 잔액

### 3.3 `/모임통장 관리` UI 3단계

#### Step 1 — 날짜 선택
- `discord.ui.Select` (string menu) 사용
- 옵션: 거래가 있는 날짜 중 최근 25개 (Select 메뉴 25개 제한)
- 각 옵션 라벨: `"📅 2026-11-28 (3건)"` 형태
- 거래가 없으면: `"등록된 거래가 없습니다."` ephemeral 응답 후 종료

#### Step 2 — 항목 선택
- `discord.ui.Select` (string menu)
- 옵션: 선택된 날짜의 거래들 (최대 25개)
- 라벨: `"📥 +50,000원 · 지각벌금 홍길동"` 형태
- 25건 초과: 처음 25개만 표시 (`"이 날 거래가 25건을 초과합니다. 최근 25건만 보입니다."` 안내)
- [↩️ 다른 날짜] 버튼으로 Step 1 복귀

#### Step 3 — 디테일 + 액션
- 임베드로 거래 디테일 표시:
  - 종류 (📥 입금 / 📤 출금)
  - 금액 (서명 포함)
  - 메모
  - 날짜
  - 등록자 (멘션) · 등록 시각
  - 현재 잔액
- 버튼 3개:
  - **[✏️ 수정]** → Modal 팝업
  - **[🗑️ 삭제]** → 확인 ephemeral
  - **[↩️ 뒤로]** → Step 2로

##### 수정 Modal (`discord.ui.Modal`)
- 필드 3개 (모두 `discord.ui.TextInput`):
  - 금액 (필수, 정수 검증)
  - 메모 (선택, 최대 200자)
  - 날짜 (필수, YYYY-MM-DD 형식 검증)
- **수정 가능 필드**: 금액, 메모, 날짜
- **수정 불가 필드**: `id`, `kind`, `user_id`(원래 등록자 유지), `ts`(원래 등록 시각 유지), `channel_message_id`
  - kind를 income↔expense 전환하고 싶다면: 삭제 후 재등록 권장
- 제출 시:
  1. 입력 검증 (금액 > 0, 날짜 YYYY-MM-DD)
  2. `_data_lock` 잡고 거래 객체 mutate (금액·메모·날짜만)
  3. `balance` 재계산 (전체 거래 sum)
  4. **잔액이 음수 되는 수정은 거부** (overdraft 정책 일관)
  5. JSON 저장
  6. 락 해제 후: `channel_message_id`가 not null이면 `await channel.fetch_message(...).edit(...)` (새 잔액 반영)
  7. `channel_message_id`가 null이면 메시지 edit skip
  8. 채널명 갱신 큐잉 (`_pending_balance`)
  9. ephemeral 응답 `"수정 완료"`

##### 삭제 확인
- ephemeral 임베드 + 빨간색 [예, 삭제합니다] / 회색 [취소] 버튼
- 확인 시:
  1. `_data_lock` 잡고 transactions에서 제거 (hard delete)
  2. `balance` 재계산
  3. JSON 저장
  4. 락 해제 후: `channel_message_id`가 not null이면 `await channel.fetch_message(...).delete()` 시도. null이면 skip.
  5. 채널명 갱신 큐잉
  6. ephemeral 응답 `"삭제 완료"`

## 4. Data Model

기존 `rss_data.json`에 `wallets` top-level 키 추가. 기존 atomic `save_data`가 미지 키 보존하므로 안전.

```json
{
  "feeds": [ /* RSS — 변동 없음 */ ],
  "wallets": {
    "<channel_id>": {
      "guild_id": "<guild_id_string>",
      "balance": 285000,
      "original_name": "운영진-방",
      "created_at": "2026-11-20T10:00:00+09:00",
      "transactions": [
        {
          "id": "0b8c2d1e-1234-4abc-9def-0123456789ab",
          "kind": "income",
          "amount": 50000,
          "memo": "지각벌금 홍길동",
          "date": "2026-11-28",
          "ts": "2026-11-28T10:15:23+09:00",
          "user_id": "987654321098765432",
          "channel_message_id": "1180000000000000000"
        }
      ]
    }
  }
}
```

### 4.1 필드 contract

| 필드 | 타입 | 필수 | 비고 |
|------|------|------|------|
| 키 (`<channel_id>`) | string | yes | `str(int)` — JSON object key는 문자열만 |
| `guild_id` | string | yes | "한 서버 1개" 제약 검증용 |
| `balance` | int | yes | KRW 정수, 음수 불가능(overdraft 거부 정책) |
| `original_name` | string | yes | `등록` 시점 채널명 (향후 reset 명령 추가 시 복원용) |
| `created_at` | string | yes | ISO-8601 + KST offset, 등록 시각 |
| `transactions[]` | array | yes | 거래 배열, **hard delete**됨 (append-only 아님) |
| `transactions[].id` | string | yes | `str(uuid.uuid4())`, 내부 식별자 |
| `transactions[].kind` | string | yes | `"income"` 또는 `"expense"` |
| `transactions[].amount` | int | yes | **양수만** (kind로 부호 결정) |
| `transactions[].memo` | string | yes | UTF-8, 0–200자 |
| `transactions[].date` | string | yes | ISO `YYYY-MM-DD` 일단위 날짜 (사용자 입력) |
| `transactions[].ts` | string | yes | ISO-8601 + KST offset, 등록 시각 (정렬용) |
| `transactions[].user_id` | string | yes | **원래 등록한** 관리자의 Discord user_id. 수정 시에도 **변경하지 않음** (감사 추적용 historical fact) |
| `transactions[].channel_message_id` | string \| null | yes | 봇이 보낸 자동 메시지 ID. send 실패 시 `null`. 수정 시 메시지 edit 가능, 삭제 시 메시지 delete 가능. `null`이면 메시지 작업 skip. |

### 4.2 불변식 (invariants)

매 명령 후 다음을 유지:
- `balance == sum(t.amount * sign(t.kind) for t in transactions)` (sign: income=+1, expense=-1)
- `balance >= 0` (overdraft 거부 정책)
- `transactions[i].date`는 유효한 ISO 날짜
- 한 `guild_id`당 최대 1개의 wallet 엔트리

### 5.2 bot.py 수정 사항 (최소)

```python

    await bot.load_extension("wallet_cog")   # +1
```

### 5.3 락 정책

- `_data_lock`은 `bot.py`에 정의되어 있음 (RSS 코드가 사용 중)
- `wallet_cog.py`에서 import: `from bot import _data_lock, load_data, save_data`
- **이유**: 같은 JSON 파일을 두 모듈이 쓰므로 락 공유 필수
- 락은 항상 `async with _data_lock:` 패턴으로만 사용
- **절대 락 안에서 `await channel.edit/send/delete`를 호출하지 않음** (deadlock & rate-limit 위험)

## 6. Rate-Limit & Concurrency

### 6.1 채널명 rate-limit 처리

Discord는 채널명을 **10분당 2회**만 변경 허용. 입금·출금·수정·삭제마다 즉시 rename하면 한도 초과 위험.

**해결**: 디바운스 + 코얼레싱 워커

```
_pending_balance: Dict[channel_id:int, desired_balance:int]
_last_rename: Dict[channel_id:int, monotonic_seconds:float]
RENAME_COOLDOWN_SECONDS = 300   # 5분 floor (안전 마진)
RENAME_WORKER_INTERVAL_SECONDS = 60
```

```
@tasks.loop(seconds=60) rename_worker_loop:
    1. _pending_balance 비어 있으면 return
    2. now = asyncio.get_running_loop().time()
    3. async with _data_lock: 스냅샷 (락 안에서 메타데이터만)
       - 처리 대상: cooldown 지난 채널들의 (ch_id, balance, name_format) 리스트
    4. 락 밖에서 await channel.edit(name=...) (개별 try/except)
       - 429: getattr(e, "retry_after") 만큼 cooldown 연장
       - 비-429 HTTPException: 큐에서 제거, WARNING 로그
       - 성공: _last_rename[ch_id] = now, _pending_balance에서 같은 값만 pop (그 사이 새 값 들어오면 유지)
```

### 6.2 동시성

- 모든 거래 명령은 `async with _data_lock:` 안에서 load → mutate → save
- 락은 RSS와 공유 (deadlock 없음 — RSS도 같은 패턴)
- View timeout 10분 — 같은 거래 동시 수정 시 마지막 쓰기 승리, stale View는 timeout으로 무력화
- `_pending_balance`·`_last_rename`은 단일 asyncio 루프 내 module dict — race 없음

## 7. Error Handling

### 7.1 권한 & 컨텍스트

| 상황 | 메시지 |
|------|--------|
| 일반 멤버 (Administrator 아님) | `"이 명령은 서버 관리자만 사용할 수 있습니다."` |
| DM 채널 | `"이 명령은 서버 채널에서만 사용할 수 있습니다."` |
| 비텍스트 채널 (Voice/Forum/Thread) | `"일반 텍스트 채널에서만 사용할 수 있습니다."` |
| 미등록 채널에서 `입금/출금/관리` | `"이 채널은 모임통장으로 등록되어 있지 않습니다. /모임통장 등록 을 먼저 실행하세요."` |
| 이미 등록된 채널에 `등록` 재실행 | `"이 채널은 이미 모임통장으로 등록되어 있습니다."` |
| 같은 서버에 다른 채널이 이미 등록 | `"이 서버에는 이미 <#기존채널> 에 모임통장이 등록되어 있습니다. 한 서버에는 한 개만 가능합니다."` |
| 봇에 `Manage Channels` 권한 없음 | `"봇에 '채널 관리' 권한이 필요합니다. 서버 설정에서 권한을 부여해주세요."` |

### 7.2 입력 유효성

| 상황 | 메시지 |
|------|--------|
| `금액 <= 0` | `"금액은 1원 이상의 정수여야 합니다."` |
| `금액 > balance` (출금) | `"잔액(285,000원)보다 큰 출금은 등록할 수 없습니다."` |
| 잘못된 날짜 형식 | `"날짜는 YYYY-MM-DD 형식으로 입력해주세요. 예: 2026-11-28"` |
| 메모 200자 초과 | `"메모는 200자 이하로 입력해주세요."` |
| 미래 날짜 | 허용 (검증 통과) |
| 너무 큰 금액으로 채널명 100자 초과 | rename 시도 → HTTPException → WARNING 로그. 거래 자체는 정상 저장. 채널명만 stale. |

### 7.3 Discord API & I/O 에러

| 상황 | 처리 |
|------|------|
| Rename 429 | retry_after 만큼 cooldown 연장, 자동 재시도 |
| Rename 403 (Forbidden) | WARNING 로그, 큐에서 제거, 다음 거래에서 재큐잉 |
| 채널 삭제됨 (404) | `bot.get_channel()` None 체크, 큐에서 제거 |
| 자동 메시지 send 실패 | WARNING 로그, **거래는 정상 저장** (JSON이 진실의 원천), `channel_message_id=null` |
| 메시지 edit 실패 (이미 삭제됨) | WARNING 로그, 거래 데이터는 정상 mutate, 사용자에게 안내 |
| 메시지 delete 실패 | WARNING 로그, 거래 데이터는 정상 제거 |
| View timeout | `interaction.edit_original_response(content="세션이 만료되었습니다. /모임통장 관리를 다시 실행해주세요.", view=None)` |

### 7.4 데이터 무결성

- JSON 손상: `load_data()` fallback (`{"feeds":[], "wallets":{}}`) — 기존 RSS 패턴 그대로
- balance invariant 위반: 매 mutate 후 `assert balance == ...` (또는 ERROR 로그 + 안내)
- 봇 재시작: `_pending_balance` 메모리 손실 → 다음 거래에서 자동 재큐잉 (허용)

### 7.5 로깅 정책

- **INFO**: 등록, 입금, 출금, 수정, 삭제 성공 (관리자 액션) + rename 성공
- **WARNING**: rename 429/403, send/edit/delete 실패, 권한 부족, JSON 손상 fallback
- **ERROR**: balance invariant 위반
