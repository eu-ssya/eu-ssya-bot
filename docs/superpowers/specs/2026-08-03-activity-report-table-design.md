# 활동 현황 보고서 표 개선 설계

**작성일**: 2026-08-03
**상태**: 승인된 출력 개선 설계
**범위**: `activity_cog.py`의 활동 현황 페이지·전체 TXT 렌더링과 보고서 행 정렬. SQLite 수집·집계 스키마와 저장 데이터는 변경하지 않는다.

## 1. 출력 계약

`/활동현황`의 Discord 응답은 PC에서 정렬되어 보이는 고정폭 코드블록 표를 사용한다. 한 페이지는 최대 15명이며, 기존 `이전`, `다음`, `전체 TXT` 버튼과 권한 동작을 유지한다.

표의 열은 아래 순서로 고정한다. Discord ID와 음성 접속 횟수는 페이지와 TXT 모두에서 제거한다.

```text
순위 이름           최근 활동          독서실       스터디     SoD EoD 활동일
  1 홍길동           2026-08-03 09:15  12시간 30분  0분         3   2      4
  2 Alice...         없음               45분         1시간 5분  1   1      2
```

- `순위`는 정렬된 전체 대상에서 시작하는 1-based 순위다. 페이지가 바뀌어도 다시 1부터 세지 않는다.
- `이름`은 표시 이름을 terminal-cell 폭 기준 14칸으로 맞춘다. 한글은 2칸, ASCII 영문·숫자·일반 기호는 1칸, 이모지는 2칸으로 계산한다. 폭을 넘으면 남은 폭 안에서 자르고 `...`를 붙이며, 후행 공백으로 채운다. 결합 문자와 variation selector는 앞 글자에 붙여 폭을 추가하지 않는다.
- `최근 활동`은 해당 행의 마지막 보존 활동 시각을 KST `YYYY-MM-DD HH:MM`으로 표시한다. 활동 기록이 없으면 정확히 `없음`으로 표시한다.
- `독서실`, `스터디`는 조회 기간에 겹친 누적 음성 시간을 사람이 읽는 형식으로 표시한다. 초 단위는 출력하지 않고, 60초 미만은 `0분`, 그 외는 분 단위로 버린 `N분` 또는 `N시간 M분`을 사용한다. 예: `0분`, `45분`, `1시간 5분`, `12시간 30분`.
- `SoD`, `EoD`, `활동일`은 기존 집계값을 그대로 표시한다. 활동일은 SoD 또는 EoD 중 하나 이상을 작성한 KST 날짜 수이며, 독서실·스터디 음성 이용일은 포함하지 않는다.

페이지 제목·기간·수집 범위 경고도 코드블록 밖의 짧은 텍스트로 유지한다. 모든 페이지 본문(설명, 코드블록, 경고 포함)은 2,000자 이하여야 한다. 행 렌더링 뒤 길이를 확인하고, 경고가 길면 경고를 먼저 축약하되 표 15행과 헤더는 축약하지 않는다.

## 2. 정렬

현재 보고서 대상 멤버를 다음 키로 안정 정렬한다.

1. `활동일` 내림차순
2. `독서실 시간 + 스터디 시간` 내림차순
3. `최근 활동 epoch` 내림차순 (`없음`은 모든 실제 시각보다 뒤)
4. 표시 이름의 `casefold()` 오름차순
5. Discord 사용자 ID 오름차순

ID는 동점 해소용 내부 키일 뿐 사용자 출력에는 포함하지 않는다. 마지막 ID 키까지 포함하므로 입력 순서와 무관하게 재현 가능한 결과가 된다.

음성 시간은 활동일을 늘리지 않으며, 활동일이 같은 경우에만 두 번째 tie-break로 사용한다.

## 3. 경고 시각과 TXT

coverage gap, 동기화 상태 등 기존 warning의 epoch는 원시 정수로 노출하지 않는다. 각 epoch를 KST `YYYY-MM-DD HH:MM KST`로 변환해 의미 있는 문장으로 표시한다. 구간 경고는 양 끝 시각을 모두 표기한다. 예: `음성 수집 공백: 2026-08-01 03:00 KST ~ 2026-08-01 05:10 KST`.

`전체 TXT`는 전체 정렬 결과를 같은 열 순서와 같은 시간·최근 활동·경고 형식으로 제공한다. TXT는 페이지당 15명 제한을 받지 않으며 Discord ID·음성 접속 횟수를 포함하지 않는다.

## 4. 권한과 비변경 사항

`/활동설정`과 `/활동현황`은 Discord 등록 시 `default_permissions(administrator=True)`를 계속 적용한다. 명령 callback과 `이전`·`다음`·`전체 TXT` 클릭은 매번 런타임 `guild_permissions.administrator`를 검사하고, 버튼은 최초 보고서 실행자만 사용할 수 있다. 등록 권한과 런타임 검사를 모두 유지한다.

SQLite 테이블, 컬럼, 수집 이벤트, 세션 계산, coverage 산정, 대상 멤버 선정 및 집계 쿼리의 의미는 바꾸지 않는다. 이번 변경은 이미 집계된 행의 표시 형식과 정렬 순서만 바꾼다.

## 5. 테스트 설계

- 한글, 영문, 이모지 표시 이름의 cell 폭 정렬을 검증하고, 긴 이름은 폭을 넘지 않으며 `...`으로 절단되는지 확인한다.
- 15명 페이지와 최대 길이의 경고·이름 조합에서 각 Discord 메시지가 2,000자 이하인지 확인한다.
- `0분`, 분만 있는 시간, 시간+분 시간이 초 없이 정확히 렌더링되는지 확인한다.
- SoD/EoD가 없는 음성 전용 행의 활동일이 0인지 확인하고, 활동일, 합산 음성 시간, 최근 활동, 이름, ID가 차례대로 적용되는 tie-break 정렬 사례를 검증한다. 최근 활동이 없는 행은 실제 시각 행 뒤에 위치해야 한다.
- recent activity의 KST 형식과 `없음`, warning epoch의 KST 설명 형식을 검증한다.
- 일반 사용자의 `/활동설정`, `/활동현황`, 페이지 버튼, 전체 TXT 접근이 거부되고, 관리자인 다른 사용자도 보고서 버튼을 사용할 수 없는 기존 admin-only 회귀를 유지한다.

## 6. 자체 검토

요구된 8개 열, 15명 페이지, 고정폭 표, ID·접속 횟수 제거, KST 시각, 시간 단위, 모든 정렬 tie-break, KST warning, 기존 버튼, 이중 관리자 보호, 데이터 모델 비변경 및 테스트 항목을 반영했다. 활동일을 SoD/EoD 전용으로, 음성 시간을 동률 해소 전용으로 명시했다. 미결 항목이 없으며, `최근 활동 없음`의 정렬 위치와 시간 반올림 규칙을 명시해 모호성을 제거했다.
